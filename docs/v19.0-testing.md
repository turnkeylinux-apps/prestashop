# PrestaShop 19.0 testing

## Scope and source decision

Debian 13 Trixie does not package the PrestaShop server. The appliance installs
the official PrestaShop 9.1.5 Classic production archive from PrestaShop's
distribution site. Upstream published 9.1.5 on 2026-08-18 as the final planned
9.1 maintenance release, including five security fixes, while 9.2 remained in
beta. The build pins and verifies SHA-256
`37140cb77c03acf61b832f76893cd8fe1e304b0fc14fa5485cfea4a7bfaf3a72`.
The distribution channel does not publish a detached digest for this archive,
so the trust boundary is the official HTTPS origin plus the repository-pinned
digest.

The appliance also installs the official Update Assistant 7.6.5 release from
the PrestaShop GitHub organization. Its pinned SHA-256,
`8cbf4b8b615bceef4710bb95708099fc5f2f64671c8196f475c87a76d6f7a2e1`,
matches the digest published with the GitHub release asset. Update Assistant
7.6.5 supports PrestaShop 9.1 and provides web and command-line update flows.

PHP 8.4, MariaDB, Apache, Postfix, Adminer and the PHP extensions come from the
signed Debian Trixie repositories. Webmin and its Apache, PHP and MariaDB
modules come from the signed TurnKey Trixie repository. PrestaShop 9.1 supports
PHP 8.1 through PHP 8.5, which includes Trixie's PHP 8.4.

The command builds the Trixie root filesystem, imports the configured root into
Docker, boots the normal systemd and firstboot path, then runs `tests/v19.sh`.

## Economical preflight evidence

The official PrestaShop metadata identified 9.1.5 as the current stable release
and 9.2 as a beta. The official system requirements declare PHP 8.4 supported
for PrestaShop 9.1. The 121,756,566-byte Classic archive was downloaded from
the official distribution origin, hashed, and inspected before source changes.
Its installer identifies PrestaShop 9.1.5 and accepts PHP 8.1 through PHP 8.5.
The Update Assistant release asset was checked against the SHA-256 digest
published by GitHub and its packaged CLI exposes the non-mutating
`update:check-new-version` command.

## Supervised updates

Take a complete database and file backup before updating. In the back office,
open Update Assistant under Advanced Parameters and review its requirement and
module compatibility checks before starting an update. The same discovery can
be run without changing the shop:

```sh
cd /var/www/prestashop
sudo -u www-data php modules/autoupgrade/bin/console \
    update:check-new-version administration
```

Debian components continue to receive normal `apt-get update` and
`apt-get upgrade` maintenance from the signed Trixie and TurnKey repositories.

## Known limitations

- Docker runtime validation does not exercise the installer, appliance kernel,
  bootloader or physical hardware. PrestaShop adds no appliance-specific
  behavior at those boundaries, so the validated Core 19 baseline supplies the
  inherited evidence.
- Application updates remain supervised because they can change database
  schema, themes and modules. Acceptance performs discovery without applying a
  vendor release.

## Deferred issues

- Paid payment gateways, affiliate networks, email delivery to public servers
  and commercial PrestaShop modules require external accounts or production
  credentials. Their individual workflows are outside appliance acceptance.
- The Classic distribution contains optional PrestaShop SA modules. Acceptance
  exercises the open-source catalog, administrator and update flows without
  enrolling the appliance in those services.
